# Flutter: UI, Cubit, Data

Рішення погоджене користувачем: Flutter/Dart із flutter_bloc/Cubit; код групується за функціями.

- `features/catalog` — CatalogCubit/State, фільтри та стан завантаження.
- `features/collections` — CollectionsCubit/State, CollectionEditorCubit/EditorState, чернетки й збережені добірки.
- `features/workspace` — WorkspaceCubit/State, зміна папки, блокування редактора під час переходу.
- `features/calculator` — CalculatorCubit/State, введення й результат.
- `features/navigation` — NavigationCubit/State, поточний розділ.
- `data/hub_repository.dart` — контракт HubRepository та FileHubRepository; файли, НБУ, вибір папки, серіалізація операцій. Workspace — низькорівневе файлове сховище.
- `pricing.dart` — незалежні фінансові формули; віджети їх не викликають.

Віджети не виконують файлових/мережевих операцій і не змінюють бізнес-стан. Діалоги підтвердження та відображення залишаються UI. Cubit управляє сценарієм, а не реалізує транспорт чи грошову арифметику.

Стани мають final-поля, @immutable та copyWith; списки/мапи захищено від змін, вкладений JSON моделей заморожено рекурсивно. Для nullable-полів є явне очищення (clearError/clearResult), тому старі помилки/результати не залишаються після нового введення.

Репозиторій послідовно виконує перемикання і записи. Нова папка стає активною лише після повного читання й збереження налаштування. Скасування або помилка не стирають чернетку. Під час вибору папки редактор заблоковано; під час запису неможливо почати другий запис чи перемикання. Успішне збереження оновлює перелік без другого читання, яке могло б помилково перетворити успішний запис на помилку через сторонній пошкоджений файл.

Підписки Cubit скасовуються у close. Асинхронні завершення перевіряють isClosed. Репозиторій та годинник інжектуються для тестів. Перевірки охоплюють відмови, повторні натискання, незмінність моделей, навігацію та збереження через UI на вузькому й широкому екранах.
