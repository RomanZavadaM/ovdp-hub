# Джерела даних і актуальність

Оновлено: 22.09.2026

OVDP Hub розділяє факт успішного отримання відповіді та актуальність самих фінансових даних.

## Обов'язкові поля observation

Для зовнішнього observation, де це можливо, зберігаються:

- sourceId і назва джерела;
- sourceUrl / evidence URL;
- ISIN;
- sourceDate або observedAt — дата/час, заявлені самим джерелом;
- retrievedAt — коли OVDP Hub фактично отримав дані;
- validUntil, якщо його дає джерело;
- freshness: current / stale / future-dated / unknown;
- kind: instrument / primary-auction / secondary-quote / tariff / manual;
- confidence: public-indicative / authenticated-indicative / executable-confirmed.

HTTP 200 означає лише успішне отримання відповіді.

## НБУ

НБУ — джерело характеристик випуску та контрактних платежів через публічний API депозитарію. retrievedAt не є датою ринку. sourceAsOf лишається unknown/null, якщо feed не дає надійної дати набору.

## Міністерство фінансів

Мінфін — окреме джерело первинного ринку:

- календар розміщень;
- оголошення конкретного аукціону;
- фактичні результати;
- обмінні аукціони та корекції.

Плановий календар і фактичний результат — різні сутності. Дані зв'язуються з інструментом за ISIN там, де ISIN оприлюднений.

## Продавці / вторинний ринок

ASK/BID yield, ціна, обсяг і тарифи — різні поля. ASK yield без ціни не стає ціною планувальника. Порожній ASK не підтверджує доступність до купівлі.

Поточний адаптер ПриватБанку перевіряє структуру таблиці й дату джерела. Старі або майбутні дати показуються як warning, а не як «актуально».

## Кеш і історія

Публічні snapshot можна кешувати локально, але старі каталоги мають retention. Збережені добірки/сценарії містять власну копію потрібних випусків і не повинні ламатися через очищення публічного кешу.
