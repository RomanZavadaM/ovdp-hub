# Швидке тестування ОВДП Hub

Повністю розпакуйте START-архів. Windows: відкрийте START.bat; macOS: START.command (за потреби `chmod +x START.command`, або `bash START.command`). Перший запуск компілює нативну оболонку лише для вашої ОС; наступні використовують кеш у цій папці. Це нативний застосунок, локальний вебсервер не запускається.

## Один раз на тестовому комп’ютері

- Flutter **3.47.5** / Dart із цього SDK. Додайте flutter до PATH або задайте FLUTTER_ROOT — шлях до папки SDK. У Windows також розпізнається попередньо встановлений SDK у Documents/Codex/tools/flutter.
- Windows: Visual Studio з компонентом **Desktop development with C++**, Windows SDK; підтримка symlink (Developer Mode або інше налаштоване середовище для Flutter plugins).
- macOS: Xcode, command-line tools і залежності плагінів за результатом `flutter doctor -v` (зокрема CocoaPods, якщо потрібен).
- Інтернет для першого завантаження залежностей. Launcher не встановлює SDK, системні компоненти або нові версії пакетів автоматично. `pubspec.lock` фіксує залежності.

Офіційні інструкції: https://docs.flutter.dev/platform-integration/windows/setup та https://docs.flutter.dev/platform-integration/macos/setup.

## Під час розробки

START залишає консоль відкритою: `r` застосовує підтримувані зміни Dart через hot reload, `R` перезапускає застосунок, `q` завершує його. Hot reload працює, коли оновлено файли у тій самій відкритій папці. Новий архів сам не оновлює вже запущену програму. Зміни нативних плагінів/оболонки потребують перезапуску й перекомпіляції.

Кожен START-пакет має власну назву з номером CI-запуску та спроби. Розпакування нової версії в нову папку означає новий локальний кеш збірки. Для найшвидшої спільної роботи розробник оновлює один робочий checkout, а ви тестуєте запущений із нього застосунок.

START — режим для тестувальника з налаштованим середовищем. Якщо його немає, використовуйте готовий пакет лише для потрібної ОС: GitHub Actions → Flutter checks and START → Run workflow → packages: windows або macos. Усі чотири платформи збираються лише при виборі all. iOS — непідписаний технічний пакет: для встановлення потрібен Apple signing. Android поки використовує тестовий підпис, не магазинний реліз.

## Дані

Робочі дані зберігаються окремо від коду. START використовує звичайний механізм вибору робочої папки; він не створює автоматично ізольовану копію ваших даних. Для експериментів виберіть копію папки через «Сховище». Особисті файли, SDK і кеш збірки до START-архіву не входять.
